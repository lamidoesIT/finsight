What it does

Four things, end to end — no manual tagging anywhere in the flow.

Reads the statement

Text extraction over the PDF, then each amount is checked against the statement's own running balance so parsing errors surface instead of hiding.

Categorises every purchase

TF-IDF over the merchant description plus engineered numeric features feed a multi-class XGBoost model covering groceries, transport, utilities and more.

Shows its confidence

Every row carries the model's probability and the runner-up category, so low-confidence predictions are flagged for review rather than presented as fact.

Compares against a budget

Set a per-category plan and FINSIGHT reports planned vs actual, what overspending cost, and progress toward a savings goal.

How the pipeline works

PDF in, categorised spending out.

  1. Extractionpdfplumber pulls date, description, amount and balance per page; a balance check validates each parsed amount.
  2. Feature engineeringStatement date parts, an inferred original purchase date, days-to-process, time of day, an online-merchant flag, and a derived transaction type (card, ATM, debit order, transfer).
  3. VectoriseTF-IDF on description + transaction type, horizontally stacked with imputed and scaled numeric features into a single sparse matrix.
  4. ClassifyXGBoost returns a probability per category; the top two are kept so confidence and the runner-up can both be shown.
  5. ExplainAggregations become plain-language insights and Plotly charts: category donut, daily stacked spend, confidence by category, planned vs actual.
